# 导航 Agent

状态：2026-11-17。对模拟游戏端开发并测试；**没有连过真游戏，也没有调用过真实的 Qwen / DeepSeek 接口**（开发环境访问不到它们）。真实模型的理解准确率要用 `agent/eval.py` 实测。

## 运行

只用 Python 标准库，不需要安装依赖。Python 3.9 以上。

```bash
# 1. 配 key（至少一个；两个都配则互为备用）。不要写进代码或提交进仓库。
export DEEPSEEK_API_KEY=...
export DASHSCOPE_API_KEY=...          # 通义千问（阿里云百炼）。key 分地域，见 agent/llm.py 里的 QWEN_BASE_URL

# 2. 先量一下模型理解得怎么样（不需要游戏）
python -m agent.eval --provider deepseek
python -m agent.eval --provider qwen

# 3. 对模拟游戏端聊天
python tools/mock_game.py --port 21777 --speedup 20        # 终端 A
python -m agent.cli --port 21777 --allow-unverified        # 终端 B

# 4. 真游戏（Windows，mod 已加载）
python -m agent.capture --list        # 哪些地点还没实测坐标
python -m agent.capture casino        # 把车停到赌场路边后执行
python -m agent.cli
```

默认模型名 `deepseek-flash`、`qwen-plus` 和接口地址是 2026-11-17 对照两家文档确认的，可用环境变量覆盖。接口报 400/404 时先检查模型名。

## 结构

| 文件 | 职责 |
| --- | --- |
| `agent/places.json` | 唯一的地名库：id、名称、别名、类别、坐标、是否实测，以及泛称（"医院"）对应哪些候选 |
| `agent/gazetteer.py` | 查库、模糊建议、歧义判断、写回实测坐标 |
| `agent/llm.py` | OpenAI 兼容接口的最小客户端，多家顺序回退 |
| `agent/nlu.py` | 一句话 → 一个经过校验的决定：本地规则 → 模型工具调用 → 确定性检查 → 关键词降级 |
| `agent/core.py` | 对话状态、方案确认、通过 TCP 执行、响应游戏事件 |
| `agent/cli.py` / `capture.py` / `eval.py` | 终端聊天、采点、评测 |

模型只做一件事：从四个工具里选一个（`propose_route` / `ask_user` / `control` / `say`）。它只能给地点 id，坐标永远由程序查库。`propose_route.stops` 是"改动后完整的剩余行程"，新建、追加、删除、替换、插入都用这一种表达，程序拿它和游戏里的当前队列做对比，再决定发追加还是整体替换。

## 各种情况怎么处理

| 情况 | 行为 |
| --- | --- |
| "停下 / 取消 / 继续 / 跳过 / 重试 / 到哪了"等固定说法 | 本地精确匹配，不经过模型，不等网络。只匹配整句，"去机场""在医院停一下"不会误触发 |
| 新路线或任何改动 | 先复述方案（改动会列出去掉和新增了什么、是否会改道），等"好 / 不"。没确认的方案不会在之后被执行 |
| 地点库里没有的地点 | 说明哪个不认识，给相近候选；不执行剩下的部分，原行程不动 |
| 泛称有多个候选（医院、警察局、回家、改车王、码头） | 追问并列出候选，可回数字。即使模型自己挑了一个，程序也会拦下来改成追问 |
| 泛称有默认项（机场、海滩） | 用默认项，并在确认里写明"按默认理解为…" |
| 地点是模型推断的（"打两杆" → 高尔夫俱乐部） | 可以，但确认里标注"根据你的描述推断" |
| 前后矛盾、说不清去哪 | 追问 |
| 模型编造 id、不调用工具、输出格式错 | 带着错误原因重试一次；仍不行就降级 |
| 模型超时、断网、接口报错、没配 key | 换下一家；都不行则降级为关键词模式：只接受"去A然后去B"这类简单句，按出现顺序匹配，明确标注并强制确认；含"不 / 改 / 换 / 加"等字样的句子直接拒绝，不猜 |
| 模型还在想，用户又说了别的（比如"停下"） | 旧结果作废，不会在停下之后又把导航启动起来 |
| 坐标未实测 | 默认拒绝导航并提示采点。`--allow-unverified` 仅用于模拟端 |
| 连不上游戏 | 明说指令没发出；停车指令失败时提示用小键盘 2 手动停 |
| 发出后没有回执（游戏暂停或开着地图） | 明说"不确定是否生效"，不报成功；之后若收到该任务的事件会补一句"其实已执行" |
| 连接中断 | 告知并自动重连，重连后核对游戏里的实际状态，以游戏为准 |
| 不在车里 | 方案保留，上车后回复"确认"重发 |
| 到达中途站 | 默认停 3 秒后自动去下一站（`--no-auto-continue` 改为等"继续"）。"就近到达"会说明离目标多远 |
| 卡住 | 自动重试 1 次；再卡住就停下来问：重试、跳过还是停下。跳过必须由用户说出，且永远不会报成"已到达" |
| 行驶中下车、车毁、死亡 | 转述暂停原因，行程保留 |
| 游戏里用热键暂停或取消、在地图上加点 | 转述，不和游戏抢控制权 |

## 已知局限

- 模型把否定句里的地点当成目的地、或漏掉一站，程序无法凭规则识别，只能靠确认环节由用户发现。评测集里有专门的用例衡量这类错误。
- 关键词模式很弱（评测集 60 条里对 22 条），它的定位是模型不可用时不至于完全不能用，而不是替代模型。
- 队列里有地图选点（没有 id 的站）时，只能追加或整体换新路线，不能重排。
- 用户输入只能来自终端。游戏内输入框转发给 Agent 还没做。
- 卡住后的恢复只有重试。倒车脱困、放宽驾驶标志要在 mod 里做，等 Windows 实测后再加。
- 持有锁等待回执时（最长 3 秒）新的输入会排队，所以极端情况下"停下"可能延迟最多 3 秒。
